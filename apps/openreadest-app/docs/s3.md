# S3 配置与同步

## 适用范围

S3 云同步支持 AWS S3 及兼容 S3 API 的对象存储，例如 MinIO、Cloudflare R2 和 Backblaze B2。桌面端、Android 和 Web 均可使用；Web 端需要 Bucket 正确配置 CORS。

## 应用内配置

打开：设置 → 集成 → 云同步 → S3

填写以下字段：

- Endpoint：对象存储的 S3 API 地址，例如 `https://s3.us-east-1.amazonaws.com`
- Region：Bucket 所在区域；Cloudflare R2 通常填写 `auto`
- Access Key / Secret Key：建议使用只允许访问目标 Bucket 和前缀的专用凭据
- Bucket Name：Bucket 名称，不要包含路径
- Remote Prefix：可选的对象 Key 前缀，例如 `openreadest/user-a`

应用会自动探测虚拟主机式和路径式访问。使用 `http://` Endpoint 时会显示安全确认；HTTP 不加密对象内容。

## 最低权限

凭据需要以下权限：

- Bucket 上、受目标前缀限制的 `s3:ListBucket`
- `{Remote Prefix}/OpenReadest/*` 上的 `s3:GetObject`
- `{Remote Prefix}/OpenReadest/*` 上的 `s3:PutObject`

首期不需要也不会调用 `s3:DeleteObject`。

## Web CORS

Web 端至少需要允许 OpenReadest 的来源执行 `GET`、`HEAD` 和 `PUT`，允许 AWS Signature V4 使用的请求头，并暴露 `ETag`。桌面和 Android 使用 Tauri HTTP 请求层，不依赖浏览器 CORS。

## 对象结构

实际对象 Key 位于 Remote Prefix 下：

```text
OpenReadest/
  Books/
    library.json
    {book.hash}/
      {safeTitle}.{ext}
      cover.png
      config.json
  System/
    sync-state.json
```

同步状态按配置隔离在本机，并在远端保存统一状态文件。S3 ETag 只作为远端版本标识，不假定等于文件 MD5。

## 首期限制

- 单次 PutObject 上传，不使用 multipart
- 不同步删除；一侧文件缺失时从另一侧恢复
- 不支持 Session Token、IAM Role、SSO、预签名 URL 或服务端加密选项
- 任一时刻只有一个 WebDAV 或 S3 配置参与自动同步
